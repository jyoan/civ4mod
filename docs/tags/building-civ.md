# 建物・文明のタグ

## 建物

| ファイル | タグ | 内容 |
|---|---|---|
| `CIV4BuildingInfos.xml` | `BuildingInfo/iPlotRadius` | その建物（陳腐化していないもの）がある都市の都市圏の半径を ○ にする（持ち主の半径の方が広ければそちら。最大 3）。FFH2 と同じ名前。説明文は `TXT_KEY_BUILDING_PLOT_RADIUS`（「都市圏の半径3」）。建設は止めない。`PlotRadiusCultureLevel`（文化レベル）を書くと、都市がその文化レベル以上のときだけ効く（説明文 `TXT_KEY_BUILDING_PLOT_RADIUS_CULTURE`「文化レベルが未熟以上で都市圏の半径3」） |
| `CIV4BuildingInfos.xml`、`CIV4TraitInfos.xml`、`CIV4CivicInfos.xml` | `AngryYieldChanges`、`AngryCommerceChanges`、`UnhealthyYieldChanges`、`UnhealthyCommerceChanges`（`BuildingInfo`・`TraitInfo`・`CivicInfo`） | 怒っている市民 1 人（`angryPopulation()`）、または不衛生 1（`-healthRate()`。食料が減る分）につき、産出や商業を足す。FFH2 のカラビムの建物に近い。建物はその都市だけ（数と陳腐化を反映）、志向と社会制度は全都市に効く。基本値に足すので、都市の産出や商業の修正を受ける。`CvCity::updateMiseryChanges()` が、都市の `doTurn`（成長と生産の前）と、人間のプレイヤーの都市の `AI_updateAssignWork()` で計算する。怒りや不衛生はさまざまな所で変わるが、その多くで市民の配置が再計算の対象（`AI_setAssignWorkDirty`）になるので、それに合わせて計算し直す（人口、建物、社会制度、幸福など）。これに乗らない変化（`changeFeatureGoodHealth` など）は次のターンから。AI の都市は `doTurn` だけ。都市画面の建物の一覧にも出す（`CyCity.getMiseryYieldByBuilding`・`getMiseryCommerceByBuilding`）。説明文は `TXT_KEY_MISERY_PER_ANGRY`・`TXT_KEY_MISERY_PER_UNHEALTHY`、都市の内訳は怒りと不衛生で別の行に出る（`TXT_KEY_MISC_HELP_YIELD_ANGRY`・`_UNHEALTHY`、`TXT_KEY_MISC_HELP_ANGRY_COMMERCE`・`TXT_KEY_MISC_HELP_UNHEALTHY_COMMERCE`）。計算結果はセーブに入る（`CvCity` の `uiFlag` 4） |
| `CIV4BuildingInfos.xml` | `BuildingInfo/PrereqAndSettledSpecialists`、`PrereqOrSettledSpecialists` | `<PrereqAndSettledSpecialist>` / `<PrereqOrSettledSpecialist>`（`SpecialistType` + `iNumSettled`（省略時 1））を何個でも書ける。`PrereqAndSettledSpecialists` は書いたすべての種類、`PrereqOrSettledSpecialists` はどれか 1 つの種類の偉人が、その都市に ○ 人以上定住していないと建てられない（両方を書くと両方が必要。ex 氏の CivGoldEmpires の中心地を参考にした）。数えるのは定住した偉人（`CvCity::getAddedFreeSpecialistCount`。建物が与える無償の専門家は含めない）。BtS の資源などの前提と同じく、建築中も毎ターン確かめ、満たさなくなると生産の列から外れる（生産力は建物に残る）。都市の定住した偉人は占領でも引き継がれて減らないので、実際に外れるのは Python やイベントで減らしたときだけ。生産の一覧には条件を満たさなくても灰色で出る（`bTestVisible` の後で判定）。説明文は「必要条件: 定住した偉大な商人1人 と 定住した偉大な芸術家1人」「必要条件: 定住した偉大な科学者1人 または 定住した偉大な技術者2人」（`TXT_KEY_SETTLED_SPECIALIST_NUM` と BtS の `TXT_KEY_AND` / `TXT_KEY_OR`。`CvGameTextMgr::buildPrereqSettledSpecialistsString`）で、ペディアでは常に、ゲーム中はそれぞれ満たさないときだけ表示 |
| `CIV4BuildingInfos.xml` | `BuildingInfo/PrereqOrBuildingClasses`、`PrereqNotInCityBuildingClasses`、`iPrereqPopulation`、`PrereqCultureLevel` | 建物の前提（Caveman2Cosmos の同名に近いタグを参考にした。第 1 段階）。別々のタグはすべて満たす必要がある。`PrereqOrBuildingClasses`（`<BuildingClassType>` の並び）: この都市にどれかの建物がある。`PrereqNotInCityBuildingClasses`（同じ書式）: この都市に書いた建物が 1 つもない。片方向なので、お互いを排他にするには両方の建物に書く。どちらも BtS の `BuildingClassNeededs` と同じく建物クラスで書くので固有建物でも通り、陳腐化した建物も「ある」と数え、その文明に建物がないクラスは無視する（`PrereqOrBuildingClasses` で使えるクラスが 1 つもなければ条件なし）。`iPrereqPopulation`: 都市の人口が ○ 以上。**生産の列に入れるときだけ**確かめる（`bContinue`。奴隷制や飢餓で減っても途中で外れない）。`PrereqCultureLevel`（`CULTURELEVEL_*`）: 都市の文化レベルが ○ 以上。4 つとも生産の一覧には灰色で出る（`CvCity::canConstruct` の `bTestVisible` の後で判定）。人口以外は建築中も確かめ、満たさなくなると生産の列から外れる（生産力は建物に残る）。両方の排他の建物を列に入れた場合は、先に完成した時点でもう片方が外れる。無料で配られる建物には効かない。すでに建っている建物が条件を失って消えることもない。そのつど判定するのでセーブデータは変わらない。説明文（`CvGameTextMgr::buildBuildingRequiresString`。ペディアでは常に、ゲーム中は満たしていない条件だけ）: `TXT_KEY_REQUIRES` + `TXT_KEY_OR`（「必要条件: 兵舎 または 穀物庫」）、`TXT_KEY_BUILDING_NOT_IN_CITY`（「同じ都市に建てられない: 兵舎, 城」）、`TXT_KEY_BUILDING_PREREQ_POPULATION`（「必要条件: 人口3以上」）、`TXT_KEY_BUILDING_PREREQ_CULTURE_LEVEL`（「必要条件: 文化レベル未熟以上」）。C2C の `PrereqInCityBuildings` は BtS の `BuildingClassNeededs` と同じ働きなので作っていない。キャッシュの形式: `CvBuildingInfo` `uiFlag=11` |
| `CIV4BuildingInfos.xml` | `BuildingInfo/PrereqOrTerrains`、`PrereqOrFeatures`、`PrereqRawVicinityBonuses`、`PrereqVicinityBonuses`、`PrereqOrImprovements` | 建物の前提の第 2 段階（C2C の Vicinity を参考にした）。都市圏に条件を求める。リストの中はどれか 1 つ、別々のタグはすべて必要。書式はそれぞれ `<TerrainType>`・`<FeatureType>`・`<BonusType>`・`<BonusType>`・`<ImprovementType>` の並び。今の半径の内側（`getNumCityPlots`。3 周目も数える）の、自チームのタイルだけを数える。別の都市が働かせているタイルも数える。`PrereqOrTerrains`: `TERRAIN_HILL` / `TERRAIN_PEAK` は丘陵・山岳のタイルを指す（丘陵のタイルは元の地形でも数える。山岳のタイルは `TERRAIN_PEAK` だけ）。`PrereqRawVicinityBonuses`: 資源があれば未開発でも可。チームに公開されている資源だけ数える（C2C と違い、一覧から隠れた資源が分からない）。`PrereqVicinityBonuses`: 開発済みの資源。`CvPlot::updatePlotGroupBonus` の条件のうち陳腐化・技術（`TechCityTrade`）・施設（都市のタイルなら施設なし）だけを見る。C2C と違い、交易網への接続と建物が生む資源は問わない。表示: 地形・特徴・未開発の資源は満たさないと**一覧に出ない**（`CvCity::canConstruct` の `bTestVisible` より前。都市では変えにくいため）。開発済みの資源と施設は灰色。どれも建築中に満たさなくなると生産の列から外れる（生産力は残る）。**`isValidBuildingLocation` には入れない**（`CvPlayer::acquireCity` が占領時に建物を残すかの判定に使うので、入れると建物が消える）。すでに建っている建物が消えることはない。そのつど判定するのでセーブデータは変わらない。リストが空の建物はタイルを調べない。説明文（`CvGameTextMgr::buildPrereqVicinityString`。ペディアでは常に、ゲーム中は満たしていない条件だけ）: `TXT_KEY_BUILDING_PREREQ_VICINITY`（「必要条件: 都市圏に 森 または ジャングル」）・`TXT_KEY_BUILDING_PREREQ_VICINITY_DEVELOPED`（「必要条件: 都市圏に開発済みの 鉄 または 銅」）。キャッシュの形式: `CvBuildingInfo` `uiFlag=12` |
| `CIV4BuildingInfos.xml` | `BuildingInfo/PrereqAndCivics`、`PrereqOrCivics` | 建物の前提の第 3 段階（C2C の同名タグを参考にした）。書式は `<CivicType>` の並び。`PrereqAndCivics` は書いた社会制度をすべて、`PrereqOrCivics` はどれか 1 つを採用していないと建てられない（`CvPlayer::canConstruct` の `bTestVisible` の後で判定するので灰色で出る）。建築中に満たさなくなると生産の列から外れる（生産力は残る）。すでに建っている建物の効果は社会制度を変えても残る（C2C の `bRequiresActiveCivics` は作っていない）。無料で配られる建物には効かない。そのつど判定するのでセーブデータは変わらない。社会制度は建物より後に読み込まれるので、種類を文字列のまま持ち（キャッシュにも文字列で書く）、`CvBuildingInfo::readPass3()` で番号に変える。名前の誤りは XML Error のメッセージで知らせる。説明文は `TXT_KEY_REQUIRES` + `TXT_KEY_AND` / `TXT_KEY_OR`（「必要条件: 原始部族社会 と 精霊崇拝」「必要条件: 世襲統治 または 検証用社会制度」。`CvGameTextMgr::buildPrereqCivicsString`。ペディアでは常に、ゲーム中は満たしていない条件だけ）。キャッシュの形式: `CvBuildingInfo` `uiFlag=13` |
| `CIV4BuildingInfos.xml` | `BuildingInfo/TechCommerceChanges`、`TechYieldChanges`、`TechHappinessChanges`、`TechHealthChanges`、`TechSpecialistChanges` | 建物の成長の第 1 段階（C2C の同名タグを参考にした）。チームがその技術を持つ間、陳腐化していない建物 1 つにつき効果が増える。書式はそれぞれ `<TechCommerceChange>`（`TechType` + `CommerceChanges`）、`<TechYieldChange>`（`TechType` + `YieldChanges`）、`<TechHappinessChange>`（`TechType` + `iHappiness`。マイナス可）、`<TechHealthChange>`（`TechType` + `iHealth`。マイナス可）、`<TechSpecialistChange>`（`TechType` + `SpecialistType` + `iSpecialistCount`）を何個でも。C2C の商業は 100 で +1 だが、この Mod は BtS の商業と同じ整数（`CommerceChanges` の 1 で +1）。読み込むと 1 つの `CvBuildingInfo::m_aBuildingChanges`（`BuildingChange`: 何に依存するか・効果の種類・番号・値）にまとめる。判定は `CvCity::isBuildingChangeActive`、1 つの建物の合計は `CvCity::getBuildingChangeTotal`。商業は `getBuildingCommerceByBuilding` でそのつど計算する。産出は世界遺産の分と同じく `CvCity::calculateDynamicBuildingYield` / `updateDynamicBuildingYields` が差分だけ `m_aiBaseYieldRate` に足す（`m_aiDynamicBuildingYield`）。幸福・衛生は `updateExtraBuildingHappiness` / `updateExtraBuildingHealth` に足す。専門家の枠は `CvCity::updateBuildingChangeSpecialists` が差分だけ足す（`m_paiBuildingChangeSpecialist`。セーブに保存、`CvCity` の `uiFlag=3`）。計算し直すのは、建物の増減と陳腐化（`processBuilding`）、技術の増減（`CvTeam::processTech` の最後の `CvPlayer::updateBuildingChangeEffects`。チームの全プレイヤー）。都市画面の産出の内訳では「建造物」の小計に含まれる。説明文は `CvGameTextMgr::buildBuildingChangesString` が常にすべて出す（「技術「陶器」で: +2[金] +1[研究]」「技術「筆記」で: 科学者の枠+1」。`TXT_KEY_BUILDING_CHANGE_TECH` / `TXT_KEY_BUILDING_CHANGE_SPECIALIST`）。キャッシュの形式: `CvBuildingInfo` `uiFlag=14`。Python は `CvBuildingInfo.getNumBuildingChanges()` と `getBuildingChangeSourceType(i)` / `Source` / `Effect` / `Index` / `Value` |
| `CIV4BuildingInfos.xml` | `BuildingInfo/BonusCommerceChanges`、`BonusYieldChanges`、`VicinityBonusYieldChanges` | 建物の成長の第 2 段階（C2C の `BonusCommercePercentChanges`・`BonusYieldChanges`・`VicinityBonusYieldChanges` を参考にした。商業は C2C と違い整数）。書式はそれぞれ `<BonusCommerceChange>`（`BonusType` + `CommerceChanges`）、`<BonusYieldChange>` / `<VicinityBonusYieldChange>`（`BonusType` + `YieldChanges`）を何個でも。`BonusCommerceChanges` / `BonusYieldChanges` は都市がその資源を使えるとき（`hasBonus`。交易網）、`VicinityBonusYieldChanges` は都市圏にその資源が開発済みのとき（`CvCity::hasVicinityBonus`。`PrereqVicinityBonuses` と同じ判定で、交易網への接続は問わない）に、陳腐化していない建物 1 つにつき増える。第 1 段階と同じ `m_aBuildingChanges` に入る（依存先 `BUILDINGCHANGE_SOURCE_BONUS` / `VICINITY_BONUS`）。計算し直すのは、資源の増減（`CvCity::updateBuildingChangesForBonus`。`processBonus` の中ではなく呼び出し側に置く。`changeNoBonusCount` は資源を失う前に `processBonus` を呼ぶため）、建物の増減。都市圏の資源はターンの初め（`CvCity::doTurn`）にも計算し直すので、施設を作ったりタイルを失ったりした分は**次のターンに**反映される。ただし、その変化で都市が資源を使えるようになった・使えなくなったときは、同じ建物が `BonusCommerceChanges` / `BonusYieldChanges` でその資源に依存していれば、`updateBuildingChangesForBonus` がすべて計算し直すので、都市圏の分もその時点で変わる。説明文は `TXT_KEY_BUILDING_CHANGE_BONUS`（「資源「銅」で: +2[金]」）・`TXT_KEY_BUILDING_CHANGE_VICINITY_BONUS`（「都市圏に開発済みの資源「鉄」で: +2[食料]」）。データの形式は第 1 段階と同じなので、キャッシュの `uiFlag` は上げていない |
| `CIV4BuildingInfos.xml` | `BuildingInfo/iHappinessPercentPerPopulation`、`iHealthPercentPerPopulation` | 建物の成長の第 3 段階（C2C の同名タグを参考にした）。陳腐化していない建物 1 つにつき、都市の人口 × ○ ÷ 100 の幸福・衛生（0 に向けて切り捨て。50 なら人口 2 につき +1、-25 なら人口 4 につき不幸・不衛生 +1）。`CvCity::getBuildingPopulationHappiness` / `getBuildingPopulationHealth` の値を `getBuildingHappiness`・`getBuildingGoodHealth` / `getBuildingBadHealth` と `updateExtraBuildingHappiness` / `updateExtraBuildingHealth` に足す。人口が変わると `CvCity::setPopulation` で計算し直し、建物の増減と陳腐化は `processBuilding` が計算し直す。セーブデータは変わらない。説明文は `TXT_KEY_BUILDING_PER_POPULATION`（「人口2につき: +1[幸福]」。100 を割り切れない値は「人口100につき: +30[幸福]」。`CvGameTextMgr::buildPerPopulationString`）。キャッシュの形式: `CvBuildingInfo` `uiFlag=15` |
| `CIV4BuildingInfos.xml` | `BuildingInfo/GlobalBuildingExtraCommerces` | 建物の成長の第 4 段階（C2C の同名タグを参考にした。C2C は建物の種類で書くが、固有建物でも効くようにクラスで書く。商業は整数）。`<GlobalBuildingExtraCommerce>`（`BuildingClassType` + `CommerceChanges`）を何個でも。この建物（陳腐化していないもの）を持つ間、持ち主の**全都市**の指定した建物クラスの建物の商業が、1 つにつき +○ 増える。この建物を複数持てば足し算。効果を受ける建物も陳腐化していない間だけ。合計は `CvPlayer::m_paiBuildingClassExtraCommerce`（クラス × 商業。セーブに保存、`CvPlayer` の `uiFlag=5`）に持ち、`CvCity::processBuilding` で足し引きする（建設・破壊・陳腐化・都市の獲得と喪失）。変わると持ち主の全都市の `updateBuildingCommerce` を呼ぶ。`getBuildingCommerceByBuilding` に足すので、都市画面の建物の一覧にも出る。説明文は `TXT_KEY_BUILDING_GLOBAL_EXTRA_COMMERCE`（「全都市の図書館: +1[研究]」。`CvGameTextMgr::buildGlobalBuildingExtraCommercesString`。その文明に建物がないクラスは出さない）。キャッシュの形式: `CvBuildingInfo` `uiFlag=16`。Python は `CyPlayer.getBuildingClassExtraCommerce(eBuildingClass, eCommerce)`、`CvBuildingInfo.getNumGlobalBuildingExtraCommerces()` / `getGlobalBuildingExtraCommerceClass(i)` / `Type` / `Value` |
| `CIV4BuildingInfos.xml` | `BuildingInfo/WorldWonderYieldChanges`、`WorldWonderCommerceChanges`、`GlobalWorldWonderYieldChanges`、`GlobalWorldWonderCommerceChanges` | 世界遺産の数に比例する効果（ex 氏の CivGoldEmpires の博物館・観光案内所）。`WorldWonder…` はその都市にある世界遺産 1 つにつき、`GlobalWorldWonder…` は持ち主の全都市の世界遺産 1 つにつき、`Yield…`（`<iYield>` は食料・生産・商業）は都市の産出に、`Commerce…`（`<iCommerce>` は金・研究・文化・諜報）は建物の商業に足す。世界遺産は陳腐化したものも数える（`CvCity::getNumWorldWonders`。BtS の 1 都市の世界遺産の上限と同じ数え方）。効果を持つ建物は陳腐化していない間だけ効く。商業は `CvCity::getBuildingCommerceByBuilding` でそのつど計算する。産出は `m_aiBaseYieldRate` に足した分を都市ごとに `CvCity::m_aiDynamicBuildingYield` に持ち（セーブに保存、`CvCity` の `uiFlag=2`）、差分だけ足し引きする（`CvCity::updateDynamicBuildingYields`）。計算し直すのは、世界遺産の数が変わったとき（`CvCity::changeNumWorldWonders`。建設・破壊・都市の獲得と喪失）と、効果を持つ建物が増減・陳腐化したとき（`CvCity::processBuilding`）で、持ち主の全都市（`CvPlayer::updateWorldWonderEffects`）。既存のセーブでは、産出の分は次に世界遺産か効果を持つ建物が増減したときに付く。説明文は BtS の産出・商業の書式で「この都市の世界遺産1つにつき: +4[商業]」「所有する世界遺産1つにつき: +1[文化]」（`TXT_KEY_BUILDING_PER_CITY_WORLD_WONDER` / `TXT_KEY_BUILDING_PER_WORLD_WONDER`）。キャッシュの形式: `CvBuildingInfo` `uiFlag=10`。Python は `CyPlayer.getNumWorldWonders()` |
| `CIV4BuildingInfos.xml` | `BuildingInfo/PyOnBuilt`、`PyOnBeginTurn` | 建物の Python フック（Python の式）。`PyOnBuilt`: 都市が生産で建物を完成したとき（`CvCity::popOrder`。無料の建物・イベント・Python で置いた建物では呼ばない）。`PyOnBeginTurn`: その建物を持つ都市（陳腐化していないもの。`getNumActiveBuilding`）の毎ターン、成長と生産の前（`CvCity::doTurn`。建物 1 種類につき 1 回）。使える名前は `pCity`・`pPlayer`（持ち主）・`eBuilding`。フックで都市を消さない。式は `EntryPoints\CvHookInterface.py` が `eval` する（ファイルの先頭に、フックごとの呼ばれる時点・使える名前・サンプル・決まりをまとめてある）。共通の関数は `CvHookUtils.py`（`gainGold`・`createUnits`・`addPromotion`・`healUnit`・`addCulture`・`isOnFeature` など。志向・呪文の Python からも使える）。ワールドビルダーでは呼ばない。キャッシュには文字列で書く。説明文にはフックの効果を出さないので、`Help` に書く |

## 文明

| ファイル | タグ | 内容 |
